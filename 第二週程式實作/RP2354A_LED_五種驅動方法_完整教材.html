01｜先把程式跑起來

五份 .ino 是五個獨立 Sketch，一次開啟並上傳一份。不可把五份程式放到同一個 Sketch 的不同頁籤，否則會重複定義 setup()、loop()。

  1. 在 Arduino IDE 2.x 的偏好設定加入 Arduino-Pico Boards Manager 網址：
    package_rp2040_index.json。
  2. Boards Manager 安裝 Earle F. Philhower 的 Raspberry Pi Pico/RP2040/RP2350 核心。本教材以 5.6.0 固定版本編譯核對，使用其內附 Pico SDK；不需要另外安裝 timer 或 PIO 函式庫。[1]
  3. 自製 RP2354A 板可從 Generic RP2350 開始，Chip Variant 選 RP2350A，Flash Size 選 2MB (no FS)，CPU Architecture 選 ARM，CPU Speed 選 150 MHz，維持一般 bare-metal 執行模式。RP2354A 的封裝內 Flash 為 2MB；不要因為 Pico 2 是 4MB 就照抄其容量。[6]
  4. 若你的板已有正確且可用的專用 board definition，優先沿用，並確認整數 7/8/9 對應 GP7/GP8/GP9。本文的 Generic RP2350 設定採直接 GPIO 編號。
  5. 解壓程式包，進入所選範例資料夾，開啟同名 .ino；按 Verify，再依板子的 BOOTSEL／USB 上傳方式燒錄。timer 與 PIO 版可開 Serial Monitor 查看錯誤訊息，設定 115200；沒有開啟監控也會啟動燈效。
本教材假設三顆是普通、獨立、以電流限流電阻驅動的 LED，不是 WS2812 等帶通訊晶片的 LED，也不是單一 RGB LED。霓虹效果指視覺上的交錯明滅／呼吸。

02｜接線、限流與 GPIO 編號

LED程式 GPIO接法點亮條件
Blue 藍色7GP7 → 電阻 → LED 陽極；陰極 → GNDHIGH
Red 紅色8GP8 → 電阻 → LED 陽極；陰極 → GNDHIGH
Yellow 黃色9GP9 → 電阻 → LED 陽極；陰極 → GNDHIGH

每顆 LED 都要各自限流。圖中 470 Ω 為低電流起始選擇；最終依 LED 的順向壓降 VF 與需要的亮度計算。電阻也可放在 LED 陰極端，只要與 LED 串聯即可。

R ≈ (3.3 V − VF) / ILED

例如紅光 VF=2.0 V、R=470 Ω，理想電流約 2.8 mA；藍光若 VF=3.0 V，則約 0.64 mA。這些 VF 是示例，請以實際元件為準。不同顏色的亮度不能只靠相同數值推定；可調整電阻或各通道最大占空比。

GPIO7 不是晶片第 7 腳，也不一定是開發板第 7 根排針。請依自製板原理圖定位 GP7/8/9。若板上已有串聯電阻，可直接沿用符合電流需求的配置。

若既有板是低電位點亮：例如 3.3V → 電阻 → LED → GPIO，本文預設極性會相反。數位版反轉 HIGH/LOW；PWM 版反轉物理輸出。這些使用 Pico SDK 的範例也可在各自 setup() 所有腳位／外設初始化完成後，加入 gpio_set_outover(pin, GPIO_OVERRIDE_INVERT)（對三個 pin 各執行一次，並 include hardware/gpio.h）；不可再同時反轉 duty，避免反轉兩次。

03｜兩個時間尺度：載波與呼吸包絡

Blinking 是肉眼可見的慢速開／關；PWM 用較高速開／關改變平均亮度；呼吸效果 再用慢速包絡去改變 PWM 占空比。方法一、二、三、五使用同一組三色交錯包絡，方法四使用數位跑馬燈。

D = tHIGH / TPWM；fPWM = 1 / TPWM
Iavg ≈ D × Ion

D 是占空比，介於 0 與 1；tHIGH 是一個週期內高電位時間；TPWM 是 PWM 週期；Ion 是 LED 點亮時的電流。平均電流公式忽略開關暫態與 LED 非線性；人眼感覺的亮度也不會與平均電流完全線性。

所有呼吸版共用的亮度函式

以 10 ms 為一格、384 格為一週期，因此 Tenv=3.84 s。藍、紅、黃的 offset 分別為 0、256、128：藍在 frame=0 最亮，紅在 frame=128 最亮，黃在 frame=256 最亮，相隔 1.28 s。

p = (frame + offset) mod 384
a = |p − 192|，0 ≤ a ≤ 192
duty = round[M × (a / 192)2]

frame 是當前影格；p 是加入色彩相位後的影格；a 是三角包絡高度；M 是最大設定值（軟體 PWM 為 64，PIO／硬體 PWM 為 255）。平方是 gamma≈2 的簡易視覺修正，不是精準的感光校準。整數式中的 36864=192²，18432 為除數的一半，用於四捨五入。先轉為 uint32_t 再相乘，避免窄整數乘法溢位。

GP7 · 藍
GP8 · 紅
GP9 · 黃
0 / 383

慢速包絡示意，可暫停拖曳；數字為 8-bit 亮度設定值。螢幕不模擬實際 PWM 邊緣、LED 電流或精確人眼亮度。

載波 312.5 Hz 或 1 kHz 與呼吸週期 3.84 s 是不同參數。提高載波頻率不會自動加快呼吸；降低 FRAME_MS 才會加快動畫。312.5 Hz 在部分相機或視線移動下仍可能呈現條紋／頻閃，不能把肉眼感覺平順視為波形量測。

04｜方法比較

方法誰產生輸出邊緣誰更新動畫目標時序前景停頓時
1 while 軟體 PWMCPU 前景CPU 前景約 312.5 Hz；64 slots停在某個 HIGH/LOW 圖樣，波形失真
2 timer IRQ 軟體 PWMCPU IRQCPU IRQ 查表20 kHz IRQ；312.5 Hz PWMIRQ 若正常，呼吸持續
3 PIO PWMPIO 狀態機CPU 前景約 1 kHz；TOP=255PWM 持續，包絡凍結
4 millis 跑馬燈CPU 前景CPU 前景每步 180 ms，無 PWM停在當前圖樣
5 硬體 PWMPWM 外設CPU 前景約 1 kHz；range=255PWM 持續，包絡凍結

前景停頓指 delay() 或耗時計算，且沒有刻意關閉中斷或時鐘。timer callback 仍占用 CPU；PIO 與 PWM 外設產生載波邊緣時不需 CPU 逐次切腳。

方法四是「排程方式」，方法五是「輸出硬體＋排程方式」；它們不是完全互斥的分類。比較焦點應是：誰掌握時間、誰產生邊緣、CPU 是否仍要供應資料。本組例子的 PWM 解析度／頻率刻意不同，適合原理比較，不適合直接當相同條件的效能基準。

05｜方法一｜while 迴圈＋軟體 PWM

CPU 親自產生每一個明滅時槽。

每次 loop() 先算三顆 LED 的亮度，再用外層 while 產生 64 個時槽；內層 while 持續檢查 micros()，等到本時槽滿 50 μs。三顆 LED 共用時槽計數器，依各自占空比同時輸出。

slot < duty[i] 是 PWM 的核心判斷。例如 duty=16，64 個時槽中的前 16 個輸出 HIGH，其餘 LOW，理想占空比就是 25%。duty=0 全暗，duty=64 全亮。

TPWM ≈ 64 × 50 μs = 3.2 ms；fPWM ≈ 312.5 Hz

這是目標值：程式執行、迴圈邊界與中斷會增加時間或造成抖動。gpio_put_masked() 一次更新指定 GPIO，避免三次 digitalWrite() 額外造成通道更新先後差；它只動到 GPIO7、8、9。

適合教：迴圈、忙等、PWM 原理、CPU 占用。限制：主程式大部分時間用於產生波形；加入耗時計算會直接拉長某些亮／暗區間。此範例沒有關閉中斷，因此 USB 和其他中斷仍可執行。

完整 Arduino 程式

01_While_SoftwarePWM.ino
#include <Arduino.h>

// GPIO numbers, not package-pin or board-header numbers.
// Active HIGH: GPIO -> resistor -> LED anode; LED cathode -> GND.
constexpr uint8_t LED_PINS[3] = {7, 8, 9}; // Blue, Red, Yellow
constexpr uint16_t OFFSETS[3] = {0, 256, 128};
constexpr uint16_t FRAME_COUNT = 384;
constexpr uint32_t FRAME_MS = 10; // One colour cycle = 3.84 s

// Triangle envelope + approximate gamma 2.0 correction.
// maximum=64 (software PWM) or 255 (PIO / hardware PWM).
uint16_t brightness(uint16_t frame, uint16_t offset, uint16_t maximum) {
  uint16_t p = (frame + offset) % FRAME_COUNT;
  uint16_t a = (p < 192) ? (192 - p) : (p - 192);
  return (uint32_t(a) * a * maximum + 18432u) / 36864u;
}

#include "hardware/gpio.h"
constexpr uint32_t LED_MASK = (1u << 7) | (1u << 8) | (1u << 9);
constexpr uint8_t PWM_STEPS = 64;
constexpr uint32_t SLOT_US = 50; // Nominal PWM: 1/(64*50us)=312.5 Hz

void setup() {
  for (uint8_t pin : LED_PINS) {
    pinMode(pin, OUTPUT);
    digitalWrite(pin, LOW);
  }
}

void loop() {
  static uint16_t frame = 0;
  static uint32_t lastFrameMs = millis();
  uint32_t now = millis();
  uint32_t steps = (uint32_t)(now - lastFrameMs) / FRAME_MS;
  if (steps != 0) {
    lastFrameMs += steps * FRAME_MS;
    frame = (frame + steps % FRAME_COUNT) % FRAME_COUNT;
  }
  uint8_t duty[3];
  for (uint8_t i = 0; i < 3; ++i)
    duty[i] = brightness(frame, OFFSETS[i], PWM_STEPS);

  uint8_t slot = 0;
  while (slot < PWM_STEPS) { // Generate one complete PWM period in software
    uint32_t beginUs = micros();
    uint32_t bits = 0;
    for (uint8_t i = 0; i < 3; ++i)
      if (slot < duty[i]) bits |= (1u << LED_PINS[i]);
    gpio_put_masked(LED_MASK, bits); // Change only GPIO7/8/9
    while ((uint32_t)(micros() - beginUs) < SLOT_US) {
      // Busy wait: CPU cannot execute other foreground work here.
      // Interrupts remain enabled, so this timing can have jitter.
    }
    ++slot;
  }
  // Arduino calls loop() again. A long task here distorts the PWM waveform.
}

06｜方法二｜timer interrupt＋軟體 PWM

以 20 kHz 計時器回呼推進 PWM 與動畫。

add_repeating_timer_us(-50, ...) 使用 Pico SDK 的 repeating timer，由 alarm pool 的計時器 IRQ 驅動回呼；不是在 loop() 裡輪詢時間。負號表示以相鄰回呼「開始時間」安排週期；正值則是上次回呼結束到下次開始的間隔。[3]

初始化先建立 384×3=1152 bytes 的亮度查表。回呼只讀表、比較、寫 GPIO 及遞增計數；不在 IRQ 中計算平方、印出訊息或等待。每 200 次回呼推進一個 10 ms 動畫影格，PWM 則每 64 次回呼完成一個週期。

activeDuty 僅在 slot=0 時更新，避免占空比在一個 PWM 週期中途改變。200 並非 64 的整數倍，因此新影格最晚延後不到約 3.2 ms 才被採用，屬於本範例的設計。

fIRQ = 1 / 50 μs = 20,000 次/s
CPU 中斷負載 ≈ fIRQ × 每次回呼執行時間

若量到每次 IRQ 約 2 μs，僅此回呼就約占 4% CPU；這是計算範例，並非實測結果。實際還有進出 IRQ 的成本。中斷被遮蔽或其他 IRQ 延遲時，50 μs 不能保證；嚴重逾時時回呼可能追趕既定時刻，PWM 邊緣仍會失真。

ledTimer 為全域物件，生命週期涵蓋整個計時器；檢查啟動回傳值，失敗時 LED 保持熄滅，序列埠每秒提示。回呼內的狀態僅由回呼存取，查表在啟動後不再修改，因此此例不需要用 volatile 假裝解決共享競爭。未來若主程式要改表，需另設同步機制。

適合教：前景與 IRQ、短中斷、時序負載。這是「timer 中斷產生軟體 PWM」，不是 PWM 硬體外設。主程式加 delay(2000) 時，只要 IRQ 正常執行，呼吸動畫仍持續。

完整 Arduino 程式

02_TimerIRQ_SoftwarePWM.ino
#include <Arduino.h>

// GPIO numbers, not package-pin or board-header numbers.
// Active HIGH: GPIO -> resistor -> LED anode; LED cathode -> GND.
constexpr uint8_t LED_PINS[3] = {7, 8, 9}; // Blue, Red, Yellow
constexpr uint16_t OFFSETS[3] = {0, 256, 128};
constexpr uint16_t FRAME_COUNT = 384;
constexpr uint32_t FRAME_MS = 10; // One colour cycle = 3.84 s

// Triangle envelope + approximate gamma 2.0 correction.
// maximum=64 (software PWM) or 255 (PIO / hardware PWM).
uint16_t brightness(uint16_t frame, uint16_t offset, uint16_t maximum) {
  uint16_t p = (frame + offset) % FRAME_COUNT;
  uint16_t a = (p < 192) ? (192 - p) : (p - 192);
  return (uint32_t(a) * a * maximum + 18432u) / 36864u;
}

#include "pico/time.h"
#include "hardware/gpio.h"
constexpr uint32_t LED_MASK = (1u << 7) | (1u << 8) | (1u << 9);
constexpr uint8_t PWM_STEPS = 64;
constexpr int64_t SLOT_US = 50;
constexpr uint16_t TICKS_PER_FRAME = 200; // 200 * 50us = 10ms
uint8_t dutyTable[FRAME_COUNT][3]; // 1152 bytes; written before timer starts
repeating_timer_t ledTimer; // Must remain alive for the timer's entire lifetime
bool timerReady = false;

bool ledTimerCallback(repeating_timer_t *timer) {
  (void)timer;
  static uint8_t slot = 0;
  static uint16_t frame = 0;
  static uint16_t envelopeTicks = 0;
  static uint8_t activeDuty[3] = {0, 0, 0};
  if (slot == 0) { // Latch all duties only at a PWM-period boundary
    for (uint8_t i = 0; i < 3; ++i) activeDuty[i] = dutyTable[frame][i];
  }
  uint32_t bits = 0;
  for (uint8_t i = 0; i < 3; ++i)
    if (slot < activeDuty[i]) bits |= (1u << LED_PINS[i]);
  gpio_put_masked(LED_MASK, bits);
  slot = (slot + 1) % PWM_STEPS;
  if (++envelopeTicks == TICKS_PER_FRAME) {
    envelopeTicks = 0;
    frame = (frame + 1) % FRAME_COUNT;
  }
  return true; // false would stop this repeating timer
}

void setup() {
  Serial.begin(115200); // Never wait for the serial monitor
  for (uint8_t pin : LED_PINS) {
    pinMode(pin, OUTPUT);
    digitalWrite(pin, LOW);
  }
  for (uint16_t f = 0; f < FRAME_COUNT; ++f)
    for (uint8_t i = 0; i < 3; ++i)
      dutyTable[f][i] = brightness(f, OFFSETS[i], PWM_STEPS);
  // Negative period requests start-to-start scheduling (not end-to-start).
  timerReady = add_repeating_timer_us(-SLOT_US, ledTimerCallback,
                                      nullptr, &ledTimer);
}

void loop() {
  static uint32_t lastMessageMs = 0;
  uint32_t now = millis();
  if ((uint32_t)(now - lastMessageMs) >= 1000) {
    lastMessageMs = now;
    if (Serial) Serial.println(timerReady ? "Timer LED running" :
                                           "ERROR: timer allocation failed");
  }
  // Even delay(2000) here would leave this IRQ-driven animation running.
  // Do not put Serial, delay(), allocation, or blocking I/O in the callback.
}

07｜方法三｜PIO state machine PWM

三個狀態機共享七條指令，各驅動一個 GPIO。

PIO 是可程式化 I/O 外設。CPU 把七條指令載入 PIO0，一顆 LED 分配一個 state machine（SM）；三個 SM 共用指令記憶體，但各自擁有暫存器、計數器、FIFO 和 GPIO 設定。[4][5]

這裡用 pio_encode_* 在 .ino 內建出指令，不需要另外安裝或執行 pioasm。ledProgram.origin=-1 允許 SDK 安排指令起點，pio_add_program() 會重定位 JMP 目標；wrap 範圍也要加上實際的 offset。

程序改寫自 Raspberry Pi 官方 PWM 範例，保留 BSD-3-Clause 授權。CPU 每 10 ms 計算亮度並送到各 TX FIFO；PIO 約每 1 ms 取一次最新待用值。FIFO 無新資料時，pull noblock 取回 X 的舊值，持續輸出原占空比，不會等 CPU。[5]

自主的部分是 PWM 載波。本範例的慢速呼吸包絡仍由 CPU 更新。主程式停頓時，PWM 波形持續，LED 保持當時的平均亮度；要讓整段動畫都不依賴 CPU 更新，可再延伸 PIO＋DMA，但本教材不把它混入入門程式。

七條 PIO 指令逐條解釋

相對位址等價組語作用
0pull noblock side 0由 FIFO 取值；若空則 X→OSR。同時令 LED LOW。
1mov x, osr把亮度比較值存入 X，供下個週期保留。
2mov y, isr載入固定 TOP=255，準備倒數。
3jmp x!=y 5尚未到比較值時，跳到 NOP 路徑。
4jmp 6 side 1X=Y 時令 LED HIGH，再跳至倒數指令。
5nop補一個時脈，讓兩條比較路徑同長。
6jmp y-- 3Y 原值非零則遞減並跳回；原值為零則結束，wrap 回 0。

ISR 同名但意義不同：這裡的 pio_isr 是 Input Shift Register（輸入移位暫存器），不是 Interrupt Service Routine（中斷服務程式）。PIO 範例並未配置 PIO 中斷。

時脈與實際占空比

Y=255…0，共 256 次，每次比較路徑均耗 3 個 PIO clock；加上週期開頭的 3 條指令：

Ncycle = 3 + 3(255 + 1) = 771
fSM = 771 × 1000 Hz = 771 kHz
divider = fsys / 771000；150 MHz 時約為 194.5525

程式由 clock_get_hz(clk_sys) 計算 divider；硬體分頻有量化，實際頻率會非常接近而非數學上完全等於 1 kHz。

此短程式不是理想的 0～100% PWM：對比較值 q∈[0,255]，HIGH 持續 3q+2 個 clock，故 D=(3q+2)/771。q=255 時約為 99.48%，不能達到恆定 HIGH；q=0 仍有短脈衝，所以程式把「亮度=0」改送 0xFFFFFFFF，確保 X 永遠不等於 Y，得到真正全暗。亮度數值愈大仍保證愈亮。

選擇 .side_set 1 opt 時，編碼函式 pio_encode_sideset_opt(1, value) 的 1 是資料位元數；設定函式 sm_config_set_sideset(&c, 2, true, false) 的 2 則包含 optional enable 位元，兩者不可誤寫成相同數值。

初始化先保持 GPIO 低電位、關閉 SM、設定 TOP 與 X，再同步啟動三個 SM。之後每個通道逐一寫 FIFO，不保證三個亮度值在完全同一個 PWM 邊界生效，但對本 LED 動畫不影響使用。put_blocking 在 FIFO 滿時仍會等待；本例每通道供應 100 筆/s、消耗約 1000 筆/s，正常情況不會累積滿載。若自行停用 SM，就不可繼續無限制寫 FIFO。

資源：PIO0 的 3 個 SM、7 條共享指令。分配失敗會保留 LED 熄滅並提示錯誤。整合其他 PIO 函式庫時要檢查資源，也不要再對這三個腳位使用 digitalWrite() 或 analogWrite() 改變輸出功能。

  uint16_t p = (frame + offset) % FRAME_COUNT;
  uint16_t a = (p < 192) ? (192 - p) : (p - 192);
  return (uint32_t(a) * a * maximum + 18432u) / 36864u;
}

#include "hardware/pio.h"
#include "hardware/pio_instructions.h"
#include "hardware/clocks.h"
// Seven-instruction PWM engine adapted from Raspberry Pi pico-examples.
// Copyright (c) 2020 Raspberry Pi (Trading) Ltd. BSD-3-Clause.
// See THIRD_PARTY_NOTICES.txt in this teaching package.
constexpr uint32_t PWM_TOP = 255;
constexpr uint32_t PWM_HZ = 1000;
constexpr uint32_t CYCLES_PER_PERIOD = 3 + 3 * (PWM_TOP + 1); // 771
PIO ledPio = pio0;
int sms[3] = {-1, -1, -1};
uint programOffset = 0;
bool pioReady = false;
uint16_t instructions[7];
pio_program_t ledProgram = {};

bool startPIO() {
  // .side_set 1 opt: 1 data bit + 1 optional-enable bit => count=2.
  instructions[0] = pio_encode_pull(false, false) | pio_encode_sideset_opt(1, 0);
  instructions[1] = pio_encode_mov(pio_x, pio_osr);
  instructions[2] = pio_encode_mov(pio_y, pio_isr);
  instructions[3] = pio_encode_jmp_x_ne_y(5);
  instructions[4] = pio_encode_jmp(6) | pio_encode_sideset_opt(1, 1);
  instructions[5] = pio_encode_nop();
  instructions[6] = pio_encode_jmp_y_dec(3);
  ledProgram.instructions = instructions;
  ledProgram.length = 7;
  ledProgram.origin = -1; // Relocatable; pio_add_program adjusts JMP addresses
  if (!pio_can_add_program(ledPio, &ledProgram)) return false;
  for (uint8_t i = 0; i < 3; ++i) {
    sms[i] = pio_claim_unused_sm(ledPio, false);
    if (sms[i] < 0) {
      for (uint8_t j = 0; j < i; ++j) pio_sm_unclaim(ledPio, sms[j]);
      return false;
    }
  }
  programOffset = pio_add_program(ledPio, &ledProgram);
  uint32_t enableMask = 0;
  for (uint8_t i = 0; i < 3; ++i) {
    uint sm = (uint)sms[i];
    uint pin = LED_PINS[i];
    pio_sm_config c = pio_get_default_sm_config();
    sm_config_set_wrap(&c, programOffset, programOffset + 6);
    sm_config_set_sideset(&c, 2, true, false);
    sm_config_set_sideset_pins(&c, pin);
    sm_config_set_clkdiv(&c, (float)clock_get_hz(clk_sys) /
                             (PWM_HZ * CYCLES_PER_PERIOD));
    pio_sm_init(ledPio, sm, programOffset, &c); // SM remains disabled
    pio_sm_set_pins_with_mask(ledPio, sm, 0, 1u << pin);
    pio_sm_set_consecutive_pindirs(ledPio, sm, pin, 1, true);
    pio_gpio_init(ledPio, pin); // GPIO output mux now belongs to PIO
    // ISR (Input Shift Register, NOT Interrupt Service Routine) stores TOP.
    pio_sm_put_blocking(ledPio, sm, PWM_TOP);
    pio_sm_exec(ledPio, sm, pio_encode_pull(false, true));
    pio_sm_exec(ledPio, sm, pio_encode_mov(pio_isr, pio_osr));
    // X=-1 cannot match Y=255..0, giving exact OFF on an empty FIFO.
    pio_sm_exec(ledPio, sm, pio_encode_mov_not(pio_x, pio_null));
    uint32_t d = brightness(0, OFFSETS[i], PWM_TOP);
    pio_sm_put_blocking(ledPio, sm, d == 0 ? 0xffffffffu : d);
    enableMask |= 1u << sm;
  }
  pio_enable_sm_mask_in_sync(ledPio, enableMask);
  return true;
}

void setup() {
  Serial.begin(115200);
  for (uint8_t pin : LED_PINS) {
    pinMode(pin, OUTPUT);
    digitalWrite(pin, LOW);
  }
  pioReady = startPIO();
}

void loop() {
  if (!pioReady) {
    if (Serial) Serial.println("ERROR: PIO0 needs 3 free SMs and 7 instructions");
    delay(1000);
    return;
  }
  static uint16_t frame = 0;
  static uint32_t lastFrameMs = millis();
  uint32_t now = millis();
  uint32_t steps = (uint32_t)(now - lastFrameMs) / FRAME_MS;
  if (steps == 0) return;
  lastFrameMs += steps * FRAME_MS;
  frame = (frame + steps % FRAME_COUNT) % FRAME_COUNT;
  for (uint8_t i = 0; i < 3; ++i) {
    uint32_t d = brightness(frame, OFFSETS[i], PWM_TOP);
    // 100 writes/s/channel; FIFO is drained about 1000 times/s/channel.
    pio_sm_put_blocking(ledPio, (uint)sms[i], d == 0 ? 0xffffffffu : d);
  }
  // CPU supplies the slow envelope; PIO autonomously repeats the last PWM.
  // No new FIFO data => pull noblock copies X into OSR (no stall).
}

08｜補充方法四｜millis 非阻塞狀態機

八個開／關圖樣，形成招牌式跑馬燈。

這個範例刻意只做數位明滅，用最簡單的狀態機呈現另一類霓虹效果：藍 → 藍紅 → 紅 → 紅黃 → 黃 → 黃藍 → 全亮 → 全暗；每步 180 ms，完整循環 1.44 s。

每次 loop() 比較經過時間，未到時間立刻返回；到時間才改圖樣。millis() 提供時基，但這不是使用者自行註冊 timer callback，燈號更新仍靠主程式輪詢。

(uint32_t)(now-lastStepMs) 利用無號減法處理 millis 回捲；不是用 now > last+interval。steps 能跳過因主程式延誤而錯過的舊圖樣，保持整體節奏；如果幾秒才執行一次 loop，肉眼仍會看到動畫停頓，非阻塞不等於自主執行。此寫法假設沒有超過整個 32 位元計時週期都不更新。

適合教：陣列、位元圖樣、有限狀態機、非阻塞排程。它不是漸變亮度版本；若要在這種排程架構加入柔和呼吸，就看下一例。

完整 Arduino 程式

04_Millis_NeonChase.ino
#include <Arduino.h>

constexpr uint8_t LED_PINS[3] = {7, 8, 9}; // Blue, Red, Yellow; active HIGH
// Bit 0=Blue, bit 1=Red, bit 2=Yellow. These are channel bits, NOT GPIO bits.
constexpr uint8_t PATTERN[] = {
  0b001, 0b011, 0b010, 0b110, 0b100, 0b101, 0b111, 0b000
};
constexpr uint32_t STEP_MS = 180;
constexpr uint8_t PATTERN_COUNT = sizeof(PATTERN) / sizeof(PATTERN[0]);
uint8_t phase = 0;
uint32_t lastStepMs = 0;

void showPattern(uint8_t bits) {
  for (uint8_t i = 0; i < 3; ++i)
    digitalWrite(LED_PINS[i], (bits & (1u << i)) ? HIGH : LOW);
}

void setup() {
  for (uint8_t pin : LED_PINS) {
    pinMode(pin, OUTPUT);
    digitalWrite(pin, LOW);
  }
  showPattern(PATTERN[phase]);
  lastStepMs = millis();
}

void loop() {
  uint32_t now = millis();
  uint32_t steps = (uint32_t)(now - lastStepMs) / STEP_MS;
  if (steps != 0) {
    lastStepMs += steps * STEP_MS;
    phase = (phase + steps % PATTERN_COUNT) % PATTERN_COUNT;
    showPattern(PATTERN[phase]);
  }
  // Other nonblocking work goes here: buttons, serial commands, sensors.
  // No delay(), no busy wait. This version intentionally uses ON/OFF only.
}

09｜補充方法五｜硬體 PWM＋millis

用 Arduino analogWrite 產生呼吸燈。

analogWriteFreq(1000) 與 analogWriteRange(255) 設定 PWM；每 10 ms 只需更新三個通道的比較值。analogWrite() 在這個 Arduino-Pico 核心使用 PWM 外設，不是 DAC 輸出連續類比電壓。[2]

GPIO7 對應 PWM slice 3 的 B 通道；GPIO8 與 GPIO9 分別為 slice 4 的 A、B 通道。GPIO8/9 共用 slice 的頻率與計數器，但占空比可以不同。本例三路都用 1 kHz，因此沒有頻率衝突。

range=255 對應 0～255 的設定值；core 負責映射，0 為全暗，255 為全亮。不要把這個 API 參數直接當成 PWM 暫存器 TOP=255；實際 divider/TOP 由 core 決定。

適合教：把「何時更新亮度」與「誰產生 PWM」分開。單純做 LED 呼吸燈，這個版本最短且 CPU 負擔低。主程式停頓時，硬體仍維持 PWM，但呼吸動畫會停在當前亮度；恢復執行後跳到依時間應有的影格。

完整 Arduino 程式

05_HardwarePWM_Breathe.ino
#include <Arduino.h>

// GPIO numbers, not package-pin or board-header numbers.
// Active HIGH: GPIO -> resistor -> LED anode; LED cathode -> GND.
constexpr uint8_t LED_PINS[3] = {7, 8, 9}; // Blue, Red, Yellow
constexpr uint16_t OFFSETS[3] = {0, 256, 128};
constexpr uint16_t FRAME_COUNT = 384;
constexpr uint32_t FRAME_MS = 10; // One colour cycle = 3.84 s

// Triangle envelope + approximate gamma 2.0 correction.
// maximum=64 (software PWM) or 255 (PIO / hardware PWM).
uint16_t brightness(uint16_t frame, uint16_t offset, uint16_t maximum) {
  uint16_t p = (frame + offset) % FRAME_COUNT;
  uint16_t a = (p < 192) ? (192 - p) : (p - 192);
  return (uint32_t(a) * a * maximum + 18432u) / 36864u;
}

constexpr uint16_t PWM_MAX = 255;
constexpr uint32_t PWM_HZ = 1000;

void setup() {
  analogWriteFreq(PWM_HZ);
  analogWriteRange(PWM_MAX); // Core maps 0..255 to duty 0..100%
  for (uint8_t i = 0; i < 3; ++i) {
    pinMode(LED_PINS[i], OUTPUT);
    analogWrite(LED_PINS[i], brightness(0, OFFSETS[i], PWM_MAX));
  }
}

void loop() {
  static uint16_t frame = 0;
  static uint32_t lastFrameMs = millis();
  uint32_t now = millis();
  uint32_t steps = (uint32_t)(now - lastFrameMs) / FRAME_MS;
  if (steps == 0) return;
  lastFrameMs += steps * FRAME_MS;
  frame = (frame + steps % FRAME_COUNT) % FRAME_COUNT;
  for (uint8_t i = 0; i < 3; ++i)
    analogWrite(LED_PINS[i], brightness(frame, OFFSETS[i], PWM_MAX));
  // Hardware keeps producing PWM between updates. Do not digitalWrite()
  // these pins while PWM should remain active: that changes the pin mux.
}

10｜課堂實驗與觀察問題

  1. 建立基本現象：依序上傳 1→2→3→4→5，確認 GP7 藍、GP8 紅、GP9 黃。呼吸版觀察亮度峰值是否按藍→紅→黃輪轉。
  2. 量測載波：以示波器／邏輯分析儀觀察 GPIO 對 GND。為方便比較，可暫時把亮度固定在軟體 PWM 32/64、硬體 PWM 128/255、PIO 比較值 128。預期週期分別約 3.2 ms、1 ms、1 ms；PIO 在 q=128 時 D=386/771，約 50.06%。
  3. 讓主程式忙碌：在各範例 loop() 的最前面暫時加入 delay(2000);。若加在 if (steps == 0) return; 後面某處，可能改變實驗執行頻率，因此統一放開頭。
  4. 比較兩種速度：將方法 5 的 PWM_HZ 改為 2000，呼吸仍是 3.84 s；再把 FRAME_MS 改為 5，呼吸縮為 1.92 s。方法 2 改影格時間時要同步修改 TICKS_PER_FRAME，它才是 IRQ 動畫的真實分頻。
  5. 比較 gamma：暫改亮度函式為 (uint32_t(a) * maximum + 96u) / 192u，取消平方。觀察低亮區與高亮區的視覺差別。
delay(2000) 實驗預期觀察解釋
while大部分時間保持某個數位圖樣，只偶爾執行一段 PWM前景停止切換腳位
timer IRQ呼吸仍持續亮度與 PWM 都在 IRQ 中推進
PIO穩定亮度維持約 2 秒後跳變PIO 仍輸出載波，CPU 只偶爾更新包絡
millis 跑馬燈圖樣停住後跳到較後面的步驟以 steps 略過已錯過的步驟
硬體 PWM穩定亮度維持約 2 秒後跳變PWM 外設自主，包絡由 CPU 更新

討論題：為什麼只把 delay() 換成 millis()，不代表 LED 已由硬體自主驅動？為什麼 PIO 使用的 ISR 不是中斷函式？為什麼主程式有 while 不代表一定會關閉中斷？

11｜排錯與參數調整

現象檢查／修正
找不到 hardware/pio.h 或 pico/time.h確認選的是 Earle Philhower Arduino-Pico 核心與 RP2350 板型；其他 Arduino core 不保證支援這些 API。
setup / loop 重複定義只開一個範例資料夾，且資料夾內只有該範例 .ino。
完全不亮先檢查 GPIO 編號、LED 極性、共同地與串聯電阻；timer／PIO 版查看序列錯誤。不要把 GPIO7 誤接成封裝 pin 7。
應該熄滅時反而最亮板子可能低電位點亮，依接線章節反轉一次輸出極性。
藍燈特別暗藍 LED 的順向壓降與發光效率不同，確認型號、電流，再調整各通道電阻或最大亮度。
timer 版閃爍／被其他工作干擾檢查是否有長 IRQ、關中斷區段、Flash 寫入或額外高頻回呼；改用方法 5 可把載波交給 PWM 外設。
PIO 分配失敗PIO0 需要 3 個空閒 SM 與 7 條指令空間。先單獨跑範例，再檢查其他函式庫占用。
PIO 亮度=0 仍微亮確認仍保留 d==0 時送 0xFFFFFFFF 的處理；直接送比較值 0 會有極短脈衝。
硬體 PWM／PIO 跑一陣子停止檢查是否又用 pinMode、digitalWrite 或其他外設接管相同 GPIO。
想加快軟體 PWM縮短 SLOT_US 會提高 CPU／IRQ 負載。timer 版也要重算 TICKS_PER_FRAME，保持「時槽數×時槽時間=影格時間」。

本教材使用一個 CPU core 的 Arduino 前景與 SDK IRQ，沒有定義 setup1() 或 loop1()。雙核心與 DMA 可作下一階段課題；教學重點是先建立可量測的時間模型。
