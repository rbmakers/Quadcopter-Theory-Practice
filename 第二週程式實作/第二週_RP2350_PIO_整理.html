RP2350 PIO 討論整理

整理範圍:PIO 硬體結構與狀態機、FSM 觀點、SPI / I²C / UART / DMA / DSHOT 實作、PIO 與內建周邊及軟體 bit-bang 的取捨。數值以 fsys=150 MHz 為例。

1 硬體結構

RP2350 有 3 個 PIO 區塊(PIO0/1/2),每塊 4 個狀態機(SM),共 12 個 SM。RP2040 為 2 塊、8 個 SM。

每個區塊共用

  • 指令記憶體:32 個 16-bit 槽位,4 個 SM 共用,各 SM 用自己的 PC 與 wrap 範圍取用。
  • IRQ flags:8 個。0–3 可送到系統中斷,4–7 僅供 SM 之間同步。
  • 輸入同步器:每腳 2-flop,可用 INPUT_SYNC_BYPASS 略過,省 2 個週期,但要自行處理亞穩態。
  • GPIO 輸出仲裁:多個 SM 驅動同一腳時,編號較高者優先。

每個 SM 私有

元件說明
PC5-bit,範圍由 WRAP_TOP / WRAP_BOTTOM 控制
X、Y32-bit 暫存器,計數與比較
OSR + 移位計數器OUT 由此移出;PULL 從 TX FIFO 載入
ISR + 移位計數器IN 移入;PUSH 送入 RX FIFO
時脈除頻器16.8 定點數:fSM=fsys/(INT+FRAC/256)
FIFOTX / RX 各 4 字,可 join 成單向 8 字(FJOIN_TX / FJOIN_RX)
腳位映射IN / OUT / SET / SIDESET 各自設定

2 指令集

只有 9 條指令,全為 16-bit:[15:13] opcode | [12:8] delay/side-set | [7:0] operands

opcode指令功能
000JMP條件跳躍(!X、X--、!Y、Y--、X!=Y、PIN、!OSRE)
001WAIT等待 GPIO / PIN / IRQ 電位
010IN從來源移入 ISR
011OUT從 OSR 移出到目的
100PUSH / PULLISR→RX FIFO / TX FIFO→OSR
101MOV暫存器搬移,可反相或位元反轉
110IRQ設定 / 清除 / 等待 IRQ flag
111SET寫入 5-bit 立即值

RP2350 新增:MOV PINDIRS、RX FIFO 隨機存取(MOV rxfifo[y],配合 FJOIN_RX_GET/PUT)、IRQ PREV/NEXT(相鄰區塊間)與 GPIOBASE 腳位窗口。

3 狀態機每週期行為

if (!SM_ENABLE)          → 保持
else if (delay_cnt > 0)  → delay_cnt--            // Delay 狀態
else:
    instr = imem[PC]
    Side-set 在指令第一個週期生效
    if (stall_condition) → 保持 PC,下週期重評估  // Stall 狀態
    else:
        執行指令
        PC = jmp_taken ? target
           : (PC == WRAP_TOP ? WRAP_BOTTOM : PC + 1)
        delay_cnt = delay 欄位
  • 每條指令 1 個 SM 週期,總耗時 = 1 + delay,時序完全可預測。
  • Delay 與 side-set 共用 5 bit:side-set 佔 n 位元時,最大 delay = 25-n-1。
  • Side-set 在指令開頭生效,即使指令 stall 也是;delay 則在指令完成後才開始倒數。
  • Stall 條件:PULL 遇 TX 空、PUSH 遇 RX 滿、WAIT 未滿足、IRQ WAIT、autopull/autopush 阻塞。
  • Wrap 不耗額外週期,是「零開銷迴圈」的來源。

時序推導

Tinst=(DIVINT+DIVFRAC/256)/fsys。小數除頻會在整數與整數+1 個 sys 週期間交替,邊沿有最多 1 個 sys 週期(6.67 ns)抖動;要精確邊沿就選能讓除數為整數(或可精確表示)的組合。

除錯

SMx_ADDR 讀 PC,SMx_INSTR 讀/寫(強制插入)指令,FSTAT / FLEVEL / FDEBUG 檢查 FIFO 與 stall/overflow。

4 用 FSM 觀點看 PIO

狀態機是否簡化邏輯

FSM 五元組 M=(S,Σ,Λ,δ,ω)。它簡化的是推理,不一定是行數:把隱含在旗標與巢狀 if 的控制流,變成可列舉、可驗證的表格。

  • 非法狀態在結構上不可表示(n 個旗標有 2n 組合,合法的往往很少)。
  • 可窮舉檢查:每個(狀態, 事件)是否有定義、有無不可達狀態或死結。
  • 每次轉移成本固定,最壞執行時間可算。

限制:狀態爆炸(平行組合為乘積)、數值運算(PID、EKF)不適合、純 FSM 只能辨識正規語言(要計數就得加擴充狀態)。

PIO 與 FSM 的對應

FSM 概念PIO 對應
狀態 sPC(最多 32 個)
轉移 δ指令記憶體內容(JMP / WAIT 決定下一個 PC)
輸入 σGPIO、FIFO 狀態、IRQ flag
輸出 ωside-set、OUT、SET
擴充狀態X、Y、OSR、ISR(嚴格說是 EFSM / FSMD)
PIO 程式「依輸入切換狀態」對一半:狀態的載體是 PC,不是獨立的 state 變數。多數 PIO 程式是「線性流程 + 迴圈」的退化形式,真正多路分支的很少。
  • 阻塞式:WAIT / PULL block / PUSH block,原地 stall 等事件,最省指令。
  • 輪詢式:JMP 條件跳躍,每週期檢查,可同時處理多個條件。

與軟體 FSM 的三個差異

  • 時序是狀態的一部分:每個狀態停多久是寫死的。
  • 沒有事件佇列:PIO 主動採樣輸入,你沒看的那個週期變化就會漏掉。
  • 狀態上限 32:靠 X/Y、OSR/ISR 承擔資料,把狀態數壓到最低(例如 UART 用 Y 數 8 次,狀態數由 O(n) 降為 O(1))。

複雜協定(如 I²C)常用 OUT EXEC 讓 CPU 透過 FIFO 餵指令,把複雜的轉移邏輯交回 CPU,PIO 只負責時序精確的那一小段。

UART

.program uart_rx
start:
    wait 0 pin 0         ; 等 start bit
    set  x, 7    [10]    ; 延遲 12 cycles,對準 bit0 中心
bitloop:
    in   pins, 1         ; 取樣
    jmp  x-- bitloop [6] ; 每圈 8 cycles = 1 bit
    jmp  pin good_stop   ; stop bit 應為高
    irq  4 rel           ; framing error
    wait 1 pin 0
    jmp  start
good_stop:
    push

核心是先延遲 1.5 bit 時間,使取樣點落在每個 bit 中央。TX 用 side-set 驅動腳位、out pins,1 移出資料。

SPI(mode 0)

.program spi_cpha0
.side_set 1
    out pins, 1  side 0 [1]   ; SCK 低:更新 MOSI
    in  pins, 1  side 1 [1]   ; SCK 高:取樣 MISO
  • 每 bit 4 cycles,fSCK=fSM/4。
  • TX FIFO 空時 out stall,side-set 已生效,SCK 停在低電位,正好是 CPOL=0 閒置。
  • 設定:MSB 優先、autopull / autopush、閾值 8。
  • 高速時輸入同步器 2 週期延遲是頻率上限主因,可 bypass 並自行補償相位。
  • CPOL / CPHA 每種模式要寫不同程式。

I²C

PIO 沒有開汲極輸出,做法是把輸出鎖存固定為 0,靠切換 pindirs 模擬:方向=輸出 → 拉低;方向=輸入 → 釋放,由上拉電阻拉高。

set  pins, 0        ; 輸出鎖存 = 0(一次性)
set  pindirs, 1     ; 拉低
set  pindirs, 0     ; 釋放
out  pindirs, 1     ; 資料位元寫入方向(資料需先反相)
wait 1 pin, 1       ; clock stretching:等 SCL 真的變高

SDK 版每 bit 32 cycles,START / STOP / 重複 START 由 CPU 把指令字塞進 FIFO,透過 OUT EXEC 執行。SDK 版要求 SCL 腳 = SDA 腳 + 1。

6 DMA

PIO 本身不搬資料,靠 DREQ:TX FIFO 未滿時 DREQ_PIOx_TXy 有效,RX FIFO 非空時 DREQ_PIOx_RXy 有效,DMA 依硬體節拍搬運,CPU 不需輪詢。

dma_channel_config c = dma_channel_get_default_config(ch);
channel_config_set_transfer_data_size(&c, DMA_SIZE_32);
channel_config_set_read_increment(&c, true);
channel_config_set_write_increment(&c, false);   // 目的地是固定 FIFO 位址
channel_config_set_dreq(&c, pio_get_dreq(pio, sm, true));  // true = TX
dma_channel_configure(ch, &c, &pio->txf[sm], buf, n, true);
  • 對 txf 做 8-bit 寫入時,匯流排會把該位元組複製到 4 個 byte lane。SPI 為左移、閾值 8,取到的是最高 8 位,所以 DMA_SIZE_8 可直接傳 uint8_t 陣列。
  • FIFO 只有 4 字,可 join 成 8 字以提高對 DMA 延遲的容忍度。

7 ESC DSHOT

幀 16 bit(MSB 先送):油門 11 bit(48–2047,0 為停止,1–47 為特殊指令)、遙測請求 1 bit、CRC 4 bit。

static inline uint16_t dshot_frame(uint16_t thr, bool telem) {
    uint16_t v   = (thr << 1) | telem;
    uint16_t crc = (v ^ (v >> 4) ^ (v >> 8)) & 0xF;
    return (v << 4) | crc;
}

位元波形:tH(1)=0.75T,tH(0)=0.375T;取 T=8 個 SM 週期,高電位分別為 6 與 3 週期。

.program dshot
.side_set 1
.wrap_target
bitloop:
    out x, 1        side 0        ; cyc 0  拉低,autopull;FIFO 空時停在低
    jmp !x do_zero  side 1 [2]    ; cyc 1-3 拉高並依 bit 分支
do_one:
    nop             side 1 [2]    ; cyc 4-6 再高 3 cycles(共 6)
    jmp bitloop     side 0        ; cyc 7
do_zero:
    nop             side 0 [3]    ; cyc 4-7 低 4 cycles(高僅 3)
.wrap
  • 兩條路徑皆 8 cycles,bit 週期恆定;out 帶 side 0 放在 bit 開頭,幀與幀之間線路停在低電位。
  • 設定:sm_config_set_out_shift(&c,false,true,16),寫入 FIFO 用 frame << 16。
  • DIV(150 MHz):DSHOT150=125、300=62.5、600=31.25、1200=15.625,皆精確。
  • 4 顆馬達:同區塊 4 個 SM 共用這份 5 條指令,以 pio_enable_sm_mask_in_sync() 同步啟動,再配 DMA 餵 FIFO。
  • 雙向 DSHOT:極性反相,送完後切成輸入接收 GCR 編碼 eRPM,需另一段接收程式。

PIO 是否為 DSHOT 首選

在 RP2350 上是:DSHOT 不是 UART / SPI / I²C 格式,內建周邊不在候選;bit-bang 抖動預算只有約 ±0.3 µs(DSHOT600)。其他 MCU 常用 timer + DMA(每 bit 一個 CCR 值,Betaflight 在 STM32 上的做法)。PIO 的優勢:腳位任意、緩衝省、多馬達同步、程式共用。不適合的情況:SM 已用完,或用的是傳統 PWM / OneShot。

8 PIO 的價值、內建周邊與 bit-bang

PIO = 可程式化的時序硬體。相對軟體 bit-bang,價值在時序由硬體保證;相對內建周邊,價值在於能做出出廠沒有的協定、補足數量、腳位任意。
更正:先前「省 CPU 只說對了一半」的說法容易被誤解成 PIO 與內建周邊的比較。其實內建周邊同樣由硬體保證時序,且更省 CPU、面積、功耗;PIO 獨有的是彈性,而不是比內建周邊更好。
面向內建周邊PIO軟體 bit-bang
波形由誰產生專用硬體 FSM可程式化 SMCPU 逐條指令
時序確定性高高受中斷 / 快取 / 匯流排影響
協定完整度完整(FIFO、校驗、流控、仲裁、target 模式)多半只做時序層自行實作
腳位固定或有限幾乎任意任意
數量固定(RP2350:2 UART、2 SPI、2 I²C)受 12 SM、32 格指令限制受 CPU 時間限制
功耗 / 面積最省SM 執行時每週期取指令佔用核心
非標準協定不行可以時序嚴格時不行

需要 bit-bang 的情況

  • 沒有 PIO 的 MCU、PIO 資源用完、腳位已定案無法改接。
  • 極低速、不在乎時序(按鈕掃描、指示燈),或一次性操作(開機讀一次 EEPROM)。
  • 異常恢復:I²C 卡死時把 SCL 切成 GPIO 手動打 9 個脈波。
  • 快速原型與除錯。

可行條件:σjitter≪ 協定時序容忍度。抖動來源:中斷搶佔、XIP Flash 快取未命中(可用 __not_in_flash_func 放進 SRAM)、匯流排競爭。使用內建周邊時不需要 bit-bang(腳位功能是 GPIO_FUNC_SPI 等,互斥於 GPIO_FUNC_SIO);CS 腳、RS-485 方向腳用 GPIO 屬於周邊之外的控制訊號,不算 bit-bang。

9 選擇順序與分工

內建周邊 → PIO → 軟體 bit-bang。標準協定、腳位與數量足夠、需要完整功能時用內建周邊;非標準時序、數量不足、腳位受限時用 PIO;最後才是 bit-bang。
CPU   ← 決策:控制律、濾波、模式管理(複雜但不緊急)
 │ 寫緩衝區
DMA   ← 搬運:依 DREQ 餵 FIFO,零 CPU 介入
 │ FIFO
PIO   ← 時序:逐 bit 精確產生波形(簡單但嚴格)
 │
GPIO / 外部裝置

PIO 的限制:指令記憶體僅 32 格、沒有內建 CRC 與封包解析、除錯門檻高、12 個 SM 是稀缺資源。對飛控而言,把馬達輸出移出 CPU 可降低控制迴圈的週期抖動,使 PID 微分項 D=Kd(ek-ek-1)/Δ t 更穩定。

實務分配:IMU 與氣壓計用硬體 SPI / I²C,GNSS 與遙控接收機用硬體 UART,DSHOT 與 WS2812 用 PIO,UART 不夠時用 PIO 補位。
