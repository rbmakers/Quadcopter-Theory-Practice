    1.3 完整四層串級結構

    把第 5、6 節的細節先在此處立體化：這套控制系統實際上是四層巢狀串級（nested cascade），由外而內依序是位置環 → 速度環 → 角度環 → 角速度環，只有最內層（角速度環）直接作用在馬達力矩上：

    \[ \underbrace{x_{sp} \to \dot x_{sp}}_{\text{位置環（外）}} \;\to\; \underbrace{\dot x_{sp} \to \phi_{sp},\theta_{sp}}_{\text{速度環}} \;\to\; \underbrace{\phi_{sp} \to \dot\phi_{sp}}_{\text{角度環}} \;\to\; \underbrace{\dot\phi_{sp} \to \tau}_{\text{角速度環（內）}} \;\to\; \text{混控} \to \text{馬達} \]

    每一層的角色是把「上一層的誤差」轉換成「下一層的設定值」，層數越內側，頻寬需求越高、迴路頻率越快（見表 1），這是串級控制的核心設計原則：內環必須比外環快至少 5–10 倍，否則外環的指令變化會落在內環的響應時間常數之內，造成耦合震盪。

    層級輸入輸出迴路頻率狀態
    位置環位置誤差 \((x_{sp}-x)\)速度設定值POSITION_RATE典型 100Hz
    速度環速度誤差角度設定值（roll/pitch）POSITION_RATE典型 100Hz
    角度環角度誤差角速度設定值ATTITUDE_RATE典型 500Hz
    角速度環角速度誤差馬達力矩指令ATTITUDE_RATE典型 500Hz
    程式碼證據 角度環與角速度環同頻執行是 確認 的：controller_pid.c 中兩者都掛在同一個 if (RATE_DO_EXECUTE(ATTITUDE_RATE, stabilizerStep)) 區塊內依序呼叫，代表這兩層雖然邏輯上是串級，但在本韌體實作中是同一個取樣週期內背靠背執行，而非各自獨立降頻——這跟教科書上「內環永遠比外環快」的一般敘述有微妙差異：這裡的加速並非來自不同執行頻率，而是角速度環的動態本身遠比角度環快，兩者共用取樣率仍然成立串級穩定性，因為角速度是角度的微分，其開迴路增益交越頻率天生就比角度環高。

    BMI088 陀螺儀的 data-ready 訊號被設定到 BMI088_INT_CHANNEL_3，實體接到 MCU 的 GPIOC Pin14，經 SYSCFG_EXTILineConfig 路由到 EXTI_Line14。STM32F4 系列的 EXTI10~15 共用同一條 NVIC 向量 （EXTI15_10_IRQHandler），向量內部須用 EXTI_GetITStatus(EXTI_Line14) 判斷是否為這條線觸發 ——本次上傳檔案未包含該向量本體，但 sensors.c 中的 EXTI14_Callback 命名與此完全對應。

    值得注意的是：只有 gyro 被設成中斷來源（bmi088_set_gyro_int_config()），accel 並未獨立配置中斷腳位。這代表整條資料鏈的節拍器是陀螺儀（1000Hz ODR），加速度計是在同一次 ISR 觸發後，於 sensorsTask 內用阻塞式輪詢讀取一併取得，兩者共用同一個時基，並非各自獨立中斷驅動。

    臨界區保護的理由 EXTI_Init() 內部需寫入 EXTI_IMR（中斷遮罩暫存器）與 EXTI_RTSR（上升緣選擇暫存器）兩個以上暫存器，若在寫入中途被更高優先權中斷打斷、而該中斷剛好去查詢 EXTI 狀態，可能讀到「遮罩已開但邊緣選擇尚未生效」的中間態，導致誤判或漏判第一次觸發。portDISABLE_INTERRUPTS()／portENABLE_INTERRUPTS() 把整個多暫存器寫入序列包成不可分割的臨界區，這是設定任何多暫存器耦合的周邊時的標準防護模式。

    2.2 ISR：資料到位事件處理

    sensors_bmi088_bmp3xx.c, sensorsBmi088Bmp3xxDataAvailableCallback() 
    void sensorsBmi088Bmp3xxDataAvailableCallback(void)
{
  portBASE_TYPE xHigherPriorityTaskWoken = pdFALSE;
  imuIntTimestamp = usecTimestamp();
  xSemaphoreGiveFromISR(sensorsDataReady, &xHigherPriorityTaskWoken);

  if (xHigherPriorityTaskWoken)
  {
    portYIELD();
  }
}

    ISR 只做三件事，刻意保持極短：

    1. 時間戳記優先——usecTimestamp() 必須在 ISR context 內第一時間呼叫，因為只有這個時間點才代表「感測器實際完成取樣」的物理真實時刻；若延後到 task context 記錄，會混入 FreeRTOS 排程延遲，時間戳記即失去校時意義。
    2. ISR-safe semaphore give——不可呼叫一般版本 xSemaphoreGive()，Cortex-M 的 NVIC 架構下 ISR 不能執行可能導致 blocking 的 API。
    3. 條件式立即讓權——portYIELD() 只在確定喚醒了更高優先權 task 時才觸發，把「中斷觸發」到「task 真正開始執行」的延遲壓到最低，不需等到下個 SysTick。

    把「感測器物理上有新資料」與「這一輪資料已經處理完成、可以安全被主控制迴圈使用」分成兩個獨立同步點，是這個架構的設計核心。若只用單一 semaphore，stabilizerTask 有可能在 sensorsTask 的 I2C 傳輸或濾波器計算都還沒完成時就被提前喚醒，讀到半殘的資料。三段式接力（硬體中斷 → 資料處理 task → 控制 task）把「不確定延遲的匯流排 I/O」完全隔離在中間層，這是後面第 3 節時序分析的結構基礎。

    STM32F405 主頻確認為 168MHz。task 優先權表確認 stabilizerTask（優先權 5）高於 sensorsTask（優先權 4）。這個安排乍看違反直覺——一般會假設「感測器讀取」該給最高優先權以降低延遲——但實際上是正確設計：

    優先權設計背後的排程邏輯 stabilizerTask 絕大多數時間阻塞在 xSemaphoreTake(dataReady, portMAX_DELAY)，不佔用 CPU。當 sensorsTask（優先權4）處理完一輪資料、呼叫 xSemaphoreGive(dataReady) 時，FreeRTOS 的搶佔式排程器會立即偵測到「有一個優先權更高（5>4）的 task 從阻塞轉為就緒」，於是立即搶佔 sensorsTask 本身、切換執行 stabilizerTask——不需要等待 sensorsTask 跑完當輪迴圈或等下一個 SysTick。這確保了控制迴圈一旦資料備妥就以最高急迫性執行，而 sensorsTask 只需要保證能穩定搶佔更低優先權的 task（LOG=1、PARAM=1 等），不需要是全系統最高優先權。

    3.3 I2C Fast Mode 傳輸時間推導

    I2C Fast Mode 時脈 \(f_{I2C} = 400\text{kHz}\)，每個 bit 週期：

    \[ T_{bit} = \frac{1}{f_{I2C}} = \frac{1}{400{,}000} = 2.5\ \mu s \]

    單一 byte 傳輸（含 ACK bit）

    \[ T_{byte} = 9 \times T_{bit} = 9 \times 2.5\ \mu s = 22.5\ \mu s \]

    一次 burst read 交易結構

    標準 I2C 讀取交易：START(1bit) + 裝置位址(1B) + 暫存器位址(1B) + 重複START + 裝置位址(1B) + N×資料位元組 + STOP。以陀螺儀 6 bytes（x/y/z 各2B）+ 加速度計 6 bytes 分兩次獨立交易估算：

    \[ T_{gyro} \approx (3\ \text{bytes 額外開銷} + 6\ \text{bytes 資料}) \times T_{byte} \approx 9 \times 22.5\mu s = 202.5\ \mu s \]

    實際韌體對加速度計與陀螺儀可能合併為單次連續 burst 讀取（視暫存器位址是否連續而定），故上表估算值（270–300µs）取兩次獨立交易與一次合併交易之間的合理區間，實際數字建議用邏輯分析儀量測 SCL/SDA 波形驗證。

    3.4 取樣定理與迴路頻率的關係

    BMI088 陀螺儀 ODR 為 1000Hz bmi088Dev.gyro_cfg.odr = BMI088_GYRO_BW_116_ODR_1000_HZ，依 Nyquist–Shannon 取樣定理，此取樣率能無混疊重建的最高訊號頻率為：

    \[ f_{Nyquist} = \frac{f_{ODR}}{2} = \frac{1000\text{Hz}}{2} = 500\text{Hz} \]

    而控制迴圈（角度環／角速度環，代表性數值 ATTITUDE_RATE=500Hz）的執行頻率恰好等於此 Nyquist 頻率。這不是巧合，而是常見的工程折衷：控制迴圈頻率設在感測器取樣率的一半，確保每次控制迴圈執行時，至少有一筆全新的感測器資料可用（實際上因為感測器 1000Hz vs 控制 500Hz，平均每次控制迴圈對應恰好 2 筆新樣本，用 xQueueOverwrite 機制自然地把多餘樣本捨棄，只保留最新值，如第2節所述）。若控制迴圈頻率設得比感測器取樣率還高，會出現「同一筆感測器資料被控制器讀取兩次以上」的資料延遲假象（stale data aliasing），這在調校 D 項增益時特別危險，因為連續兩次讀到相同值會讓微分項瞬間掉到零，產生虛假的高頻震盪抑制錯覺。

    4.1 兩層濾波架構總覽

    這套韌體的雜訊抑制分成兩個完全獨立的層級，各自有不同的設計目的：

    層級位置作用對象可否關閉

    步驟一：連續時間二階 Butterworth 原型

    二階 Butterworth 低通濾波器的定義特徵是「最大平坦（maximally flat）」通帶響應，其標準化（截止頻率正規化為 \(\Omega_c=1\)）轉移函數為：

    \[ H(s) = \frac{1}{s^2 + \sqrt{2}\,s + 1} \]

    分母的 \(\sqrt{2}\) 係數對應阻尼比 \(\zeta = \dfrac{1}{\sqrt{2}} \approx 0.707\)，這正是 Butterworth 濾波器（相對於 Chebyshev、Bessel 等其他濾波器族）的定義性質：二階系統阻尼比為 \(1/\sqrt2\) 時，頻率響應在通帶內二階導數為零、無峰值（無 Q 值突起），故稱「最大平坦」。程式碼中 2.0f*cosf(M_PI_F/4.0f) 正是 \(2\cos(\pi/4) = 2 \times \frac{\sqrt2}{2} = \sqrt2\) 的浮點展開寫法。

    步驟二：頻率預變形（Pre-warping）

    標準雙線性轉換 \(s = \frac{2}{T}\cdot\frac{1-z^{-1}}{1+z^{-1}}\) 會把類比頻率軸做非線性壓縮（頻率翹曲，frequency warping），若不修正，實際數位濾波器的截止頻率會偏離設計目標。修正方法是先用預變形公式算出「修正後的類比截止頻率」\(\omega_{pre}\)，讓映射後恰好落在目標數位截止頻率上：

    \[ \omega_{pre} = \tan\!\left(\frac{\pi f_c}{f_s}\right) \]

    這正是程式碼中 ohm = tanf(M_PI_F/fr)，其中 fr = sample_freq/cutoff_freq，故 M_PI_F/fr = π·cutoff_freq/sample_freq，與上式完全對應。

    步驟三：代入雙線性轉換並化簡

    以 \(s \leftarrow \omega_{pre}\cdot\dfrac{1-z^{-1}}{1+z^{-1}}\) 代入步驟一的 \(H(s)\)，兩邊乘以 \((1+z^{-1})^2\) 整理後可得：

    \[ H(z) = \frac{\omega_{pre}^2(1+z^{-1})^2}{c + 2(1-\omega_{pre}^2)z^{-1} + (\omega_{pre}^2-\sqrt2\,\omega_{pre}+1)z^{-2}} \] \[ \text{其中}\quad c = 1+\sqrt2\,\omega_{pre}+\omega_{pre}^2 \]

    將分子分母同除以 \(c\)，即得程式碼中的五個係數 \(b_0,b_1,b_2,a_1,a_2\)：

    \[ b_0=b_2=\frac{\omega_{pre}^2}{c},\quad b_1=\frac{2\omega_{pre}^2}{c},\quad a_1=\frac{2(\omega_{pre}^2-1)}{c},\quad a_2=\frac{\omega_{pre}^2-\sqrt2\,\omega_{pre}+1}{c} \]

    步驟四：正確性驗證（直流增益與 Nyquist 增益）

    代入 \(z=1\)（直流，\(z^{-1}=1\)）：

    \[ H(1)=\frac{b_0+b_1+b_2}{1+a_1+a_2}=\frac{4\omega_{pre}^2/c}{4\omega_{pre}^2/c}=1 \]

    代入 \(z=-1\)（Nyquist 頻率 \(f_s/2\)，\(z^{-1}=-1\)）：

    \[ H(-1)=\frac{b_0-b_1+b_2}{1-a_1+a_2}=\frac{0}{\cdots}=0 \]

    直流增益恰為 1（低頻訊號完全通過，無衰減），Nyquist 頻率增益恰為 0（最高頻雜訊完全濾除），兩者皆符合低通濾波器的物理預期，驗證推導與程式碼一致。

    4.3 頻率響應（供第7節相位裕度計算使用）

    在取樣率遠高於分析頻率範圍的前提下（本系統 \(f_s=1000\text{Hz}\)，分析頻段落在數十 Hz 量級），可直接使用步驟一的連續時間原型計算增益與相位，數位效應造成的誤差可忽略：

    令 \(x = \omega/\omega_c = f/f_c\)，則：

    \[ |H(jx)| = \frac{1}{\sqrt{(1-x^2)^2+2x^2}} \qquad \angle H(jx) = -\arctan\!\left(\frac{\sqrt2\,x}{1-x^2}\right) \]

    於截止頻率處（\(x=1\)）：

    \[ |H(j1)| = \frac{1}{\sqrt{0+2}} = \frac{1}{\sqrt2}\ (-3.01\text{dB}) \qquad \angle H(j1) = -90° \]

    此為 Butterworth 濾波器的定義性質：截止頻率處增益恰為 \(-3\text{dB}\)、相位落後恰為 \(90°\)，兩極點各貢獻 45°。

    4.5 為何角速度用 80Hz、加速度計用 30Hz：頻寬需求與雜訊來源的權衡

    感測器前端濾波器截止頻率的選擇反映了兩個訊號各自不同的用途與雜訊特性：

    • 陀螺儀（80Hz）：直接作為角速度環的量測回授，是控制頻寬鏈中相位裕度最敏感的一環（見第7節）。80Hz 截止頻率在 ATTITUDE_RATE（代表性數值 500Hz）的迴路頻率下，仍能保留足夠通帶頻寬，讓控制器能對更高頻的擾動作出反應；若截止頻率設太低，會侵蝕角速度環原本就緊繃的相位裕度。
    • 加速度計（30Hz）：主要用途是為姿態融合（sensfusion6.c）提供重力方向的低頻參考，其量測本質上受到螺旋槳氣動與機構振動耦合的高頻雜訊污染最嚴重（四軸機加速度計最主要的雜訊來源就是機架振動，頻率通常落在馬達轉速的基頻與諧波，遠高於姿態變化本身的頻率），30Hz 已足夠涵蓋姿態變化的實際物理頻寬，同時大幅衰減振動雜訊。

    這是「感測器濾波器設計必須考慮訊號下游用途，而非只看訊號本身頻譜」的具體案例：同一顆 IMU 的兩軸資料因為下游用途不同（一個是快速回授、一個是慢速姿態參考），濾波策略也應該不同。

    5.1 pidUpdate() 演算法逐步拆解

    pid.c, pidUpdate() 
    pid->error = pid->desired - measured;
// (yaw專用) 誤差跨越±180°時的環繞修正

pid->outP = pid->kp * pid->error;                       // ① 比例項
output += pid->outP;

float delta = -(measured - pid->prevMeasured);           // ② 對「量測值」微分，非對「誤差」微分
// (yaw專用) delta跨越±180°時的環繞修正
pid->deriv = enableDFilter ? lpf2pApply(&pid->dFilter, delta/pid->dt) : delta/pid->dt;
pid->outD = pid->kd * pid->deriv;
output += pid->outD;

pid->integ += pid->error * pid->dt;                       // ③ 積分累加（矩形積分法）
pid->integ = constrain(pid->integ, -pid->iLimit, pid->iLimit);  // ④ 積分限幅（anti-windup）
pid->outI = pid->ki * pid->integ;
output += pid->outI;

pid->outFF = pid->kff * pid->desired;                     // ⑤ 前饋項
output += pid->outFF;

output = constrain(output, -pid->outputLimit, pid->outputLimit);  // ⑥ 總輸出限幅
pid->prevMeasured = measured;

    ① 微分對「量測值」而非「誤差」微分

    程式碼註解明確說明理由：若對誤差 \(e=r-y\) 微分，當設定值 \(r\) 瞬間跳變時，微分項會出現一個瞬間尖峰（derivative kick），因為 \(\dot e\) 在階躍瞬間理論上趨近無限大。改為對量測值 \(y\) 微分（\(\dot y\)，符號取負號使其等效於誤差微分在穩態時的行為），设定值跳變不會直接反映在微分項上，只有「實際測到的物理量變化速度」才會，這在飛控上尤其重要，因為姿態設定值經常因搖桿指令瞬間改變。

    ④ 積分限幅式 Anti-windup

    本實作用的是最簡單直接的 anti-windup 手法：先累加、後夾限（clamping），而非更精細的 back-calculation 或 conditional integration。當控制器輸出已經飽和（例如電池電壓不足、馬達已全力輸出）時，若不限制積分項持續累加，會造成「積分飽和」（windup）——誤差持續存在、積分持續增長，等到誤差終於反轉時，龐大的積分量需要很長時間才能消退，造成明顯的超調（overshoot）與振盪。pidSetIntegralLimit() 把這個上限做成可獨立設定的參數，讓每一軸、每一層迴路可以有不同的積分容忍度。

    • 角度環 roll/pitch 的 \(K_d=0\)：外環完全不用微分項，只有 P+I。這是串級架構的典型設計——外環的「微分抑制」功能實質上由內環（角速度環）承擔，因為角速度本身就是角度的微分，內環直接量測並控制這個微分量，外環再疊加一個 D 項在數學上是部分冗餘的。

    5.4 Yaw 角度環繞處理

    pid.c ／ controller_pid.c

    Yaw 角度以 \([-180°,180°]\) 表示時會在邊界產生不連續（例如從 179° 變到 -179°，物理上只轉了 2°，數值上卻是 358° 的跳變）。pidUpdate() 用 isYawAngle 旗標對誤差與微分量分別做環繞修正：

    \[ e_{yaw} = \begin{cases} e - 360° & \text{if } e > 180° \\ e + 360° & \text{if } e < -180° \\ e & \text{otherwise} \end{cases} \]

    此外，attitudeControllerGetYawMaxDelta()（第1輪分析已確認於 controller_pid.c）額外限制 yaw 設定值與目前 yaw 的最大差距（YAW_MAX_DELTA，預設值 0.0，即停用），避免 velocity 模式下 yaw 設定值無限累積導致與實際 yaw 差距過大。

    第1輪分析已確認 controller_pid.c 在 setpoint->mode.roll == modeVelocity 切換瞬間呼叫 attitudeControllerResetRollAttitudePID()，本節可進一步用 pidReset() 的實作確認其效果：

    void pidReset(PidObject* pid, const float actual)
{
  pid->error        = 0;
  pid->prevMeasured = actual;   // 避免下一次微分計算對到「舊模式」的量測值
  pid->integ        = 0;
  pid->deriv        = 0;
}

    prevMeasured 被設為目前實際量測值而非 0，這確保 reset 後第一次呼叫 pidUpdate() 時，微分項的 delta = -(measured - prevMeasured) 恰好為 0，不會因為 prevMeasured 殘留舊模式的值而在切換瞬間產生虛假的微分尖峰——這與 5.1 節「微分對量測值而非誤差微分」的設計動機一致，reset 邏輯必須配合這個設計正確初始化，否則模式切換本身就會製造出原本要避免的 derivative kick。

    6.1 全域座標到機體偏航座標的旋轉變換

    position_controller_pid.c, positionController() 
    float cosyaw = cosf(state->attitude.yaw * (float)M_PI / 180.0f);
float sinyaw = sinf(state->attitude.yaw * (float)M_PI / 180.0f);

float setp_body_x =  setpoint->position.x * cosyaw + setpoint->position.y * sinyaw;

    位置控制器不直接在全域座標系（world frame）下運作，而是先把全域 X/Y 座標旋轉到「機體偏航對齊座標系」（body-yaw-aligned frame，只旋轉 yaw 角、不旋轉 roll/pitch）：

    \[ \begin{bmatrix}x_{body}\\y_{body}\end{bmatrix} = \begin{bmatrix}\cos\psi & \sin\psi\\-\sin\psi & \cos\psi\end{bmatrix} \begin{bmatrix}x_{world}\\y_{world}\end{bmatrix} \]

    這是標準的二維旋轉矩陣（旋轉角 \(-\psi\)，即把世界座標系逆旋轉機體目前的偏航角，得到機體視角下的座標）。這樣做的理由：位置環的輸出（速度誤差 PID 的下一層）最終要轉換成 roll/pitch 姿態設定值，而 roll/pitch 的物理定義本來就是相對機體座標系（機頭方向）而非世界座標系——「向前傾」跟「向北傾」是兩回事，除非機頭剛好朝北。把位置誤差先轉到機體座標系，後續 PID 的輸出才能直接對應到「往前/往側邊傾斜多少度」，不需要在每一層都重複做座標轉換。

*thrust = constrain(*thrust, 0, UINT16_MAX);
    \[ \text{thrust} = \text{clip}\Big(\ \underbrace{\text{PID}_{VZ}(v_{z,sp}-v_z)}_{\text{速度誤差修正量，約 }\pm\text{個位數}} \times \underbrace{1000}_{\text{thrustScale}} \ +\ \underbrace{36000}_{\text{thrustBase，代表性懸停推力}}\ ,\ \ 20000,\ 65535\ \Big) \]

    這是一個加法式前饋 + 修正的結構：thrustBase（36000，或 baro-hold 模式 38000）是「預期懸停所需的基礎推力」，速度 PID 的輸出只需要修正「實際懸停推力與這個基準值的差距」，而不需要從零開始把整個懸停推力都用積分項堆出來。這大幅降低了 PID 積分項需要處理的動態範圍，也是為什麼 VZ 速度環積分限幅（見表格未列出，繼承 DEFAULT_PID_INTEGRATION_LIMIT）不需要設得特別大的原因——積分項只需要修正基準值的誤差，不需要憑空建構整個推力量級。thrustMin（20000）則確保即使速度 PID 輸出大幅負值（例如快速下降指令），推力也不會低到讓馬達完全停轉、失去姿態控制能力。

    7. 頻寬裕度計算推導

    本節數值定位 第4、5節的濾波器係數與 PID 增益已全數確認，可直接代入本節公式。但完整求出精確相位裕度還需要兩個未確認項：（1）機體轉動慣量 \(J\)，（2）PID 輸出（PWM 尺度）與物理力矩之間的混控增益 \(K_{mix}\)（即 Legacy 模式下 control->roll 每單位對應多少 N·m，需要馬達推力曲線在實際工作點的斜率，定義於未上傳的 motors_def.c）。本節先建立完整符號推導方法（不依賴這兩項，可直接套用任何實際系統），再用一組代表性交越頻率示範數值計算流程，並在7.6節建議用您熟悉的 relay feedback 實驗方法取得實際交越頻率，繞開這兩個未知項。

    7.1 開迴路轉移函數建構（角速度環為例）

    以 roll 軸角速度環為分析對象，這是整條串級中頻寬需求最高、相位裕度最緊繃的一環。開迴路轉移函數由四個環節串聯構成：

    \[ L(s) = \underbrace{C(s)}_{\text{PID控制器}} \cdot \underbrace{G(s)}_{\text{機體轉動平面模型}} \cdot \underbrace{F(s)}_{\text{感測器LPF}} \cdot \underbrace{e^{-sT_d}}_{\text{總延遲}} \]

    控制器 \(C(s)\)（confirmed，第5.2節）

    \[ C(s) = K_p + \frac{K_i}{s} + K_d s \qquad (K_p=250,\ K_i=500,\ K_d=2.5) \]

    注意：第4.4節已確認角速度環 D-filter 預設關閉，故 \(C(s)\) 的微分項不含額外濾波器極點，直接是理想微分 \(K_d s\)——這代表 \(C(s)\) 在高頻的相位貢獻會持續趨近 \(+90°\)，沒有濾波器把這個相位領先「收回來」，這是預設關閉 D-filter 對頻寬裕度的直接影響，7.5節會回頭討論這點的利弊。

    機體平面模型 \(G(s)\)

    剛體繞單軸轉動的歐拉方程（忽略陀螺耦合項，單軸線性化近似）：\(J\dot\omega = \tau\)，故：

    \[ G(s) = \frac{1}{Js} \]

    這是一個純積分器，物理意義是「力矩的時間積分等於角動量變化」。此模型忽略空氣阻尼項（實際上螺旋槳氣動阻尼會在 \(G(s)\) 分母多一個一階項 \(J s + b\)，但阻尼係數 \(b\) 通常遠小於慣性項在此頻段的貢獻，忽略不影響方法示範）。

    感測器濾波器 \(F(s)\)（第4.3節已推導）

    \[ F(s) = \frac{\omega_c^2}{s^2+\sqrt2\,\omega_c s+\omega_c^2}, \qquad \omega_c = 2\pi \times 80\text{Hz} = 502.65\ \text{rad/s} \]

    總延遲 \(e^{-sT_d}\)（第3節時序分析 + ZOH半週期）

    \[ T_d = \underbrace{300\ \mu s}_{\text{I2C+ISR+運算，confirmed量級}} + \underbrace{\frac{1}{2}\times\frac{1}{500\text{Hz}}}_{\text{ZOH半取樣延遲，representative頻率}} \approx 1.3\ \text{ms} \]

    零階保持器（Zero-Order Hold）造成的延遲來自「數位控制器的輸出在下一次取樣前維持不變」，其平均相位延遲效應等效於半個取樣週期的純延遲，這是數位控制系統分析的標準近似（在交越頻率遠低於取樣頻率時成立，本系統交越頻率預期在數十Hz量級，取樣頻率500Hz，比例超過10倍，近似有效）。

    7.2 各環節相位貢獻公式

    積分器（來自 \(G(s)\)）

    \[ \angle G(j\omega) = -90°\quad(\text{對所有頻率恆定}) \]

    PID 控制器相位

    \[ C(j\omega) = K_p + j\Big(K_d\omega - \frac{K_i}{\omega}\Big) \quad\Rightarrow\quad \angle C(j\omega) = \arctan\!\left(\frac{K_d\omega-K_i/\omega}{K_p}\right) \]

    低頻時 \(K_i/\omega\) 項主導，相位趨近 \(-90°\)（積分器行為）；高頻時 \(K_d\omega\) 項主導，相位趨近 \(+90°\)（微分器行為）；中間必有一個頻率使虛部為零、相位恰為 \(0°\)，稱為 PID 的「相位領先中心頻率」：

    \[ \omega_{PID,0} = \sqrt{\frac{K_i}{K_d}} = \sqrt{\frac{500}{2.5}} = \sqrt{200} \approx 14.14\ \text{rad/s} \approx 2.25\text{Hz} \]

    感測器濾波器相位（第4.3節公式）

    \[ \angle F(j\omega) = -\arctan\!\left(\frac{\sqrt2\,(\omega/\omega_c)}{1-(\omega/\omega_c)^2}\right) \]

    延遲相位

    \[ \angle e^{-j\omega T_d} = -\omega T_d \ \text{[rad]} = -360°\times f\times T_d \]

    7.3 代表性交越頻率下的數值計算

    交越頻率的取得方式 精確交越頻率 \(\omega_{gc}\)（\(|L(j\omega_{gc})|=1\) 之處）需要 \(J\) 與 \(K_{mix}\) 才能從 \(|L(j\omega)|\) 反解。此處採用文獻中常見的 Crazyflie 級小型四軸機角速度環交越頻率量級（約 20–30Hz）作為代表性示範值，取 \(f_{gc}=25\text{Hz}\)（\(\omega_{gc}=157.08\text{ rad/s}\)）示範完整計算流程；7.6節會說明如何用實驗方法取得您實際系統的精確交越頻率，取代這個示範值。
    環節計算相位貢獻
    積分器 \(G(j\omega)\) 恆定 −90.00°
    PID 控制器 \(C(j\omega)\) \(\arctan\!\big(\frac{2.5\times157.08-500/157.08}{250}\big)=\arctan\!\big(\frac{392.7-3.18}{250}\big)\) +57.32°
    感測器LPF \(F(j\omega)\)，\(x=25/80=0.3125\) \(-\arctan\!\big(\frac{\sqrt2\times0.3125}{1-0.3125^2}\big)=-\arctan(0.4897)\) −26.10°
    總延遲，\(T_d=1.3\text{ms}\) \(-360°\times25\times0.0013\) −11.70°
    開迴路總相位 \(\angle L(j\omega_{gc})\) 加總 −70.48°

    相位裕度定義與計算

    \[ PM = 180° + \angle L(j\omega_{gc}) = 180° + (-70.48°) = 109.52° \]
    結果判讀 在此代表性交越頻率下，相位裕度高達約 \(110°\)，遠超過控制系統設計常見的安全下限（\(45°\)–\(60°\)）。這個結果主要來自 PID 微分項在此頻率貢獻的顯著相位領先（\(+57.32°\)），部分抵銷了積分器（\(-90°\)）、感測器濾波器（\(-26.1°\)）與延遲（\(-11.7°\)）的相位落後。這樣的數字組合本身即說明：\(K_d\) 的相位領先效果，是這套增益配置能撐住感測器延遲與濾波器相位落後的主要來源，也解釋了為何角速度環的 \(K_d\)（2.5）雖然數值上遠小於 \(K_p\)（250），卻仍是穩定性關鍵的一環，不可忽視其重要性。惟此數字高度依賴代表性交越頻率的假設，實際數字務必以7.6節實驗方法驗證。

    7.4 若啟用角速度環 D-filter（30Hz）：相位裕度的損失量化

    第4.4節指出角速度環 D-filter 預設關閉。若使用者依 rateFiltEn 參數開啟（截止頻率 30Hz，確認值），\(C(s)\) 的微分項會多一個由 lpf2p（第4.2節同一濾波器）造成的額外相位落後，在 \(f=25\text{Hz}\)、\(f_c=30\text{Hz}\)（\(x=0.833\)）之下：

    \[ \Delta\phi_{Dfilter} = -\arctan\!\left(\frac{\sqrt2\times0.833}{1-0.833^2}\right) = -\arctan\!\left(\frac{1.178}{0.306}\right) = -75.4° \]

    這是一個非常顯著的額外相位落後——幾乎與交越頻率本身同量級（30Hz 濾波器在 25Hz 已經逼近其截止頻率），若疊加進7.3節的計算，相位裕度會從 \(109.52°\) 驟降至約 \(34°\)，逼近甚至跌破一般設計安全下限。這正是為什麼 ATTITUDE_RATE_LPF_ENABLE 預設關閉的合理工程理由：D-filter 的截止頻率（30Hz）與代表性交越頻率（25Hz）過於接近，貿然開啟反而可能讓迴路更接近不穩定邊緣，除非同時調降迴路增益或提高濾波器截止頻率做搭配調整。這是本文件中「濾波器降雜訊」與「濾波器降相位裕度」兩個效果直接對撞的具體數值案例，對 CURIO 課程教材而言，這組對照計算（開/關 D-filter 導致 \(109.52°\to34°\) 的裕度差異）本身就是一個很好的教學示範：濾波器不是加了就穩定，加錯位置反而可能讓系統更接近失穩邊界。

    7.5 建議：以 Relay Feedback 實驗取代純分析模型

    7.3節的交越頻率是文獻代表值，非本系統實際量測值，主因是 \(J\) 與 \(K_{mix}\) 未知。與其花時間精確量測轉動慣量與混控增益再代入本節公式，更直接的做法是用繼電回授自激振盪（relay feedback）直接量測系統在臨界穩定點的實際交越頻率與增益——這正是您已經在 CURIO 平台上發展的 Åström–Hägglund 方法：在角速度環迴路中插入一個 relay（bang-bang 開關），系統會在某個頻率下自發產生等幅振盪，該振盪頻率就是相位滯後恰為 \(180°\) 處的頻率（即 \(\angle L(j\omega_{osc})=-180°\)），振盪幅值與 relay 幅值的比例則直接給出該頻率下的開迴路增益 \(|L(j\omega_{osc})|\)。這個實驗量到的單一資料點，比本節整條需要 \(J\) 與 \(K_{mix}\) 才能畫出的解析 Bode 曲線更可靠，因為它是系統的直接量測結果，不受簡化平面模型（忽略空氣阻尼、忽略陀螺耦合）誤差影響。若您要把本文件用於 CURIO 課程教材，建議在本節之後銜接您既有的 relay feedback autotuning 教材，形成「解析法建立直覺 → 實驗法取得精確數字」的完整教學閉環。
